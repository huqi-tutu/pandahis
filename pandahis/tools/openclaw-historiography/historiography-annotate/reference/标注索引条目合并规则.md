# 标注索引条目合并规则

> **定位**：介于「标注规则」与「翻译规则」之间的独立 SSOT。  
> 标注阶段只产出**著作级** skeleton 条目（`SHIJI_*` / `HANSHU_*`）；跨卷、跨著作整合在本规则中定义，产出**全局级**条目（`GLBL_*`）。  
> **本文件不修改标注流水线 Step1–4 的行为**；合并由人工或后续 merge 工具执行。

---

## 一、术语

| 术语 | 含义 |
|------|------|
| **史略主题** | 以 `史略名称`（及必要时的别名归一）标识的人物、政权、专题 |
| **著作级 ID** | skeleton 内 `史略ID`，如 `SHIJI_089_01`、`HANSHU_058_01` |
| **全局级 ID** | 合并后新建 `GLBL_*`，与著作级 ID 并存、互引 |
| **主要史料** | 合并条目的母本来源；翻译时 `role=母本` |
| **补充史料** | 同主题其他出处；翻译时 `role=补充` |
| **卷型** | 专传 / 合传 / 群像传 / 纪（本纪、列传纪体） |

---

## 二、卷型判定

| 卷型 | 判定 |
|------|------|
| **专传** | 卷名或条目结构以**单一传主**为主（如《贾谊传》《田儋列传》《匈奴列传》） |
| **合传** | 卷名或 `protagonists_manifest` 为**多人合传**（如《张耳陈馀传》《魏豹田儋韩王信传》） |
| **群像传** | 儒林、酷吏、游侠、货殖、佞幸、循吏等**专题类**列传 |
| **纪** | 本纪、×帝纪、高后纪等纪体；与专传同级优先；**吕后虽为纪体，史略分类仍归宗戚**（见 §五） |

**蕃祚**类人物/政权：史记常为**蕃祚专传**（如《匈奴列传》《南越列传》），汉书常为**蕃祚合传**（如《西南夷两粤朝鲜传》）——卷型优先级与人物相同：**专传 > 合传**。

---

## 三、主要 / 补充判定（优先级从高到低）

### 规则 1　专传 / 纪 > 合传 > 群像传

若同一史略主题同时出现在多种卷型中：

1. **专传** 或 **纪**（本纪、帝纪等）→ 主要史料  
2. **合传** → 补充史料  
3. **群像传** → 补充史料  

同卷型内（如两书皆有纪、或两书皆为专传）→ 适用规则 2。

**例**

- **贾谊**：汉书 058 专传（主）← 史记 084 合传、汉书 061 无贾谊（已修正为贾山）  
- **董仲舒**：汉书 066 专传（主）← 史记 121、汉书 101 儒林（补）  
- **张汤**：汉书 070 专传（主）← 史记 122、汉书 103 酷吏（补）  

### 规则 2　同卷型 → 著作时间顺序

若卷型相同（均为专传、均为合传、均为纪、均为群像等），取**二十四史中成书更早**的著作为主要史料，其余为补充。

- 著作先后以史籍编号为准：`01史记` < `02汉书` < …  
- **例**：汉高祖 — 史记 008 本纪（主）← 汉书 001上+001下（补，合并为一单元）  

**仅群像、无专传无合传时**：两书皆有群像段落 → 仍按规则 2，**先著群像为主**（史记 121 > 汉书 101）。

### 规则 3　同书分卷 = 一卷

同一著作内上下 / 上中下拆分，合并时**先拼接段界，再整体赋 role**，不得遗漏。

- 例：汉书 067+068 司马相如、107+108 匈奴、115+116+117 王莽  
- 例：史记无分卷则单卷引用  

### 规则 4　纪体内的宗戚

**吕太后**：史记有本纪、汉书有高后纪，但**史略分类统一为宗戚**，不归君王。主次仍按规则 2（纪 vs 纪 → 史记 009 主，汉书 004 与 112 外戚段为补）。

## 四、合并产物结构（草案）

```json
{
  "史略ID": "GLBL_042_01",
  "史略名称": "张耳",
  "史略分类": "文臣",
  "source_entries": [
    { "史略ID": "SHIJI_089_01", "role": "主要" },
    { "史略ID": "HANSHU_042_01", "role": "补充" }
  ],
  "paragraphs": [
    { "work": "01史记", "volume": "089", "paragraph_from": 2, "paragraph_to": 40, "role": "母本" },
    { "work": "02汉书", "volume": "042", "paragraph_from": 2, "paragraph_to": 35, "role": "补充" }
  ]
}
```

- 新建 **`GLBL_*`** 作为全局入口  
- **保留**各著作级 `SHIJI_*` / `HANSHU_*`，不得删除  
- `paragraphs[]` 内 `role` 与 `source_entries[].role` 一致  
- **不写入** `_auto_filled`（标注流水线过程字段，与顶层史略字段重复）  
- 母本 skeleton 的考订说明提取为顶层 **`考订依据`**（可选）：`年`、 `坐标主轴`、 `年规则`、 `年规则备注`  
- GLBL 正式字段（坐标、年份、ID 等）以顶层为准；改 GLBL 时只改顶层，不重跑 merge 则 skeleton 不回写

## 六、与翻译规则的关系

| 层级 | 文件 | 职责 |
|------|------|------|
| 标注 | `人物标注规则.md` 等 | 单卷 skeleton、段界、分类 |
| **合并** | **本文件** | 跨卷/跨著作主补、GLBL 索引 |
| 翻译 | `翻译规则.md` | 以合并后母本顺译，补充按 role 融入 |

翻译规则中的「母本 / 补充」术语与本文件「主要 / 补充史料」一一对应；**本文件不写入翻译规则正文**。

## 七、判定流程

```
收集同一史略主题的全部著作级条目
  → 按卷型排序（专传 > 合传 > 群像 > 纪）
  → 取最高卷型中成书最早者 = 主要史料
  → 同书分卷先合并
  → 其余 = 补充史料
  → 应用 §五 分类修正
  → 输出 GLBL_* + source_entries 映射
```

## 九、GLBL ID 稳定性（强制）

- **已发布的 `GLBL_*` 为主键**，翻译、DB（`historical_box.id`）、用户足迹均依赖此 ID
- **禁止**全量重跑 `merge_global_entries.py` 覆盖既有索引（会按排序重新编号全部 GLBL）
- 数据修复须**外科手术式**：
  1. 直接编辑 `史略索引_01至02.json` 合并/删除/扩充条目
  2. 或运行专用 `repair_*.py`（须显式保留既有 GLBL ID）
  3. 删除重复条目时**只删多余 GLBL**，保留 canonical 条目的原 ID
- 新增跨著作合并主题时，分配**未使用的最大序号 +1** 的 GLBL ID，勿挤占或重排已有编号
