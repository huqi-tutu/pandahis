# 朝代全局优先级（P0–P3）标注规则

> 覆盖字段：`优先级` / `优先级判定理由`（直接改写，非卷内叙事权重）。
> 脚本：`dynasty_priority.py`
> **仅在全局 enrichment 阶段运行**；卷级 Step4 / skeleton **不得**写入优先级初值。

## 一、定义

**在同一 `朝代ID` 内**，按该史略主题（人物/政权/事件）在**整个朝代历史叙事中的重要性**，横向比较后定级：

| 级别 | 含义 |
|------|------|
| **P0** | 朝代级核心：定鼎者、重大转折君主、顶级名臣名将、改变格局的事件/政权 |
| **P1** | 重要但非顶层：有名专传、关键配角、区域性强权 |
| **P2** | 史籍有独立叙事、可检索，但非大众认知核心 |
| **P3** | 边缘：单段提及、世系链、工具性人物 |

数字越小优先级越高。

## 二、判定原则

1. **朝代内横向比较**：与同朝所有史略分类（君王/文臣/武将/宗戚/宦官/蕃祚/庶众）一起排，不是卷内主轴。
2. **君王 ≠ 自动 P0**：短命幼主、边缘诸侯多为 P2/P3；仅开国/盛世/重大转折者 P0。
3. **分类链不参与升降**：比的是历史影响力，不是「君王 > 文臣」。
4. **蕃祚** 按政权在当朝分量定级（如匈奴 vs 小方国）。
5. **峰值年/峰值原因** 可作辅助，但优先级看整体历史地位，不是生卒中点。

## 三、配额（脚本软约束）

每朝 P0 上限 ≈ `max(2, min(30, round(条目数 × 9%)))`，防止全员 P0。超出时脚本将溢出 P0 降为 P1 并标待审。

## 四、输出

```json
{"史略ID":"GLBL_xxx","优先级":"P1","优先级判定理由":"理由须点名史略名称"}
```
