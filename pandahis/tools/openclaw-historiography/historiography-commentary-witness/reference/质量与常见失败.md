> 与 `评述遴选规则.md` / `见证遴选规则.md` 配套。解释**为何产出容易偏差**，以及工作流上还能补什么。

## 质量偏差从哪来（根因）

1. **结构门禁强、语义门禁弱**  
   verify 能抓字数、ID、撞书名（正史论赞可破）、翻译体标记、软关联 P0、顾颉刚占比、人物类缺论赞（WARN）；**抓不住**「这段其实只是在记事」「五条其实是同一框架换皮」「呜呼但无史臣曰的伪欧公体」。

2. **主流条目有「教材答案」**  
   黄帝/禅让/五帝战事 → 模型默认掏层累、逼篡、神话历史化；边缘人物（夔、嫫母）反而被迫深挖，质量更高。

3. **批次无在途记忆**  
   逐条串行 compose 时看不到「本朝已写过 19 次顾颉刚」；朝代配额是**事后**检查，不能防止当时写歪。

4. **详情与评述职责重叠**  
   详情已把囚尧/逼尧写成罗生门；评述若再用别的书讲同一情节，读者感到「详情翻版」，即使未撞主书名。

5. **见证默认「有坟就上」**  
   上古传说陵、村碑被当成「唯一实物」→ 违反空结果勇气；规则已改，存量未全量重跑则观感仍偏。

6. **Prompt 过长、缺少金样**  
   整份规则塞进一次调用，尾部约束易被稀释；缺少「像嫫母/夔那样」的 few-shot 正例。

## 建议的下一轮优化（尚未全部代码化）

| 优先级 | 项 | 说明 |
|--------|----|------|
| P0 | **存量按新规重跑** | 五帝评述顾颉刚 66%、软关联 P0 见证等，规则已生效但数据仍是旧产 |
| P1 | **Prompt 金样** | 在 `cw_lib` 注入 1 条评述正例 + 1 条见证正例（短），压过教材套路 |
| P1 | **批次在途配额** | `compose_dynasty` 每写一条前读 manifest：顾颉刚已达阈值则本条 prompt 禁止再引 |
| P2 | **君王/大事专规** | 第 1 条禁止教材框架（已有）；再要求至少 1 条「非疑古、非禅让真假」的冷门来源 |
| P2 | **详情叙事去重** | 从详情正文抽「已讲述的冲突标签」（逼尧/囚尧等），评述禁止同标签复述 |
| P3 | **人工抽检清单** | 每朝代抽 3 主流 + 3 边缘对照读，比只看 verify 绿更重要 |

## 人工快速品控（一条史略）

评述：

- [ ] 五条能否一句话说清「在争什么」？
- [ ] 有没有「记录当评述」？
- [ ] 有没有翻译体或末尾再贴书名？
- [ ] 顾颉刚是否在抢片尾？能不能删？

见证：

- [ ] P0 是 A+/A/B，还是现代碑/传为陵？
- [ ] 若全是 E，是否应改为 `已处理·无可用`？
- [ ] 制度类是否写了时间跨度？
