# Step：补全成稿（Phase 2）

## 任务

在 Phase 1 **母本顺译稿** 基础上，穿插索引补充与外部补全，写出最终 `翻译详情` 并落盘 JSON。

## 规则

**只遵守**消息中已注入的规则节选（唯一 SSOT：`翻译规则.md`）。

## 纪律

1. **母本骨架不可重写**：保留 Phase 1 的句序、原词锚点与信息点；只允许在 plan 锚点处 **插入** 或 **轻量扩写**，禁止大段删改母本已译内容。
2. **外部补全准入**：只采用 `source_plan.外部补全` 中 `"采用": true` 的项；每项须：
   - 挂 `母本锚点`（某 M 编号前/后）；
   - 写明出处（《书名·卷篇》）；
   - 提供 **母本没有** 的信息：异说、冲突观点、背景、细节、评价差异；
   - **禁止** 把母本已述事实换说法再写一遍。
3. **索引补充**：按 `索引补充处理` 中「引入|异说」项融入；「去重不用」的不得写入。
4. **异说独立**：多版本须分述，禁止调和为一个版本。
5. 文末必须有 `*参考著作：*` 列表（母本 + 实际引用的他书）。
6. **禁模糊出处**：不得使用「据说、相传、传说、有人说、有资料说」等；凡他书信息须写「《书名·卷》载：…」。地理传说要么删除，要么挂出处。
7. **引用白名单**：仅可使用 `source_plan.允许引用白名单` 中的著作；不得自行添加 plan 未列书目。
8. **禁止元叙述**：`翻译详情` 第一行必须是正文叙事，**不得**写「本条 N 段…已读完」等喊数/进度汇报（那是动笔前自检，不是读者正文）。


9. **前置引入（必须）**：在 `翻译详情` 正文开头，先写一段引入（约 100-200 字），
   交代**阅读框架**（为何从这段原文读起、在全书/本纪中的位置），再自然过渡到正文。

   | 要求 | 说明 |
   |------|------|
   | 引入职责 | **阅读框架**，不是人物小传；回答「为何从这里读起」 |
   | 禁止重复 | **不得**写入 `前置引入禁区` 及 `母本首句预览` 中 M001–M003 将覆盖的身世/品貌/早年（如姓公孙、生而神灵） |
   | 可用素材 | 仅限 `前置引入素材` 中的朝代/类别/一句话定位/史料源头 |
   | 不可编造 | 不得添加素材之外的朝代、身份、时代信息 |
   | 过渡 | 引入与正文之间须有自然过渡句（如「让我们来看一看《史记》如何记载…」） |
   | 段落 | 引入 1-2 段，写出厚度感，不碎 |

10. **归因纪律**：正文前部**不得**展开非本传主的退场/葬地（如颛顼篇不写黄帝崩）；本传主母本缺漏的退场句，在**正文尾部**补入（见 `本传缺漏补全`）。


## 输入

- Phase 1 `母本顺译` 全文
- `source_plan`（外部补全、索引补充、参考著作）
- `recalled`（核对锚点）

## 输出

```json
{ "史略ID": "…", "翻译详情": "…\n\n*参考著作：*\n1. …" }
```

**仅写 `史略ID` 与 `翻译详情`。** `史料原文` 由编排器写入。

完成后回复 `TRANSLATE_DONE` + 史略ID + 约字数。
