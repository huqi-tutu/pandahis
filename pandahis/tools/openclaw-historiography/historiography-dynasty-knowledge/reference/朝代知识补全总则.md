## 零、读者交付物（权威）

### 0.1 是什么

二期朝代知识补全的**唯一读者交付物**，是入库前写入 `data/06朝代知识补全/详情/{史略ID}_{名称}.json` 的字段 **`翻译详情`**。

该字段**原样**用于小程序史略详情页正文展示（事略 / 典制 / 论著 / 人物七类均同）。读者打开条目后，应读到一篇：

- **完整的**：围绕本条主题（人物 / 事件 / 典制 / 论著）有头有尾，起承转合齐全，合段收束后不悬空
- **流畅的**：口语叙事、段落连贯，像在读文章，不像在读条目说明、编辑备注或质检报告
- **可读的**：面向具备通识文史素养的读者；无小标题、无列表、无课件感

**文体标杆**：《明朝那些事儿》——有画面、有节奏、史家第三人称、克制幽默；风格细则对齐 `historiography-compose/references/翻译规则.md`，写作约束见 `详情写作_共用规范.md` **§0**。

### 0.2 不是什么（禁止混入正文）

下列内容属于**中间产物或工作语言**，**不得**出现在 `翻译详情` 中：

| 类型 | 示例 | 应存放位置 |
|------|------|------------|
| 锚点 / checklist | hard_facts、forbidden_inventions | `06/锚点/`、`logs/` |
| 质检说明 | 「正文不宜补写…」「读者能把握的是…」「本条须落定的硬史实」 | `logs/verify/`、`logs/reviews/` |
| 写作禁令 | 「不得把神话当作硬事实」「若谈史实边界…」 | prompt / 审校规则 |
| 撰写蓝图 | 起承转合要点、信息点表 | `附录/工作流说明` Phase A（可选） |

防幻觉、过程禁编、锚点覆盖是**创作约束**，不是**正文话术**。史实留白应写成史书的沉默（如「太史公六字带过，战局细节已不可考」），不得写成对模型或读者的写作指南。

### 0.3 验收标准与两层质检分工

| 层级 | step | 负责什么 | 不负责什么 |
|------|------|----------|------------|
| **校本（硬检）** | `verify-detail` | 字数、段落、格式、【】/列表、**AI 腔词频**、元叙述短语、锚点字面覆盖 | 语义级幻觉、过程是否编造、文章好不好读 |
| **审校（Kimi）** | `review-detail` | **幻觉/禁编**、异说边界、**读者向整体可读性** | 重复 verify 已硬检项（见 `详情审校规则.md` §2） |

入库前须同时满足：

1. **格式**：`朝代补全格式规范.md`
2. **读者交付物**：`详情写作_共用规范.md` §0
3. **类型结构**：类型专属撰写规则（起承转合、信息点）
4. **verify-detail**：无 error 级 issue
5. **review-detail**：Kimi `overall_verdict` 非 fail（warn 可人工接受）

**合格定义**：verify 无 error，且 Kimi 非 fail；说明文腔、知识硬伤任一出现均不可交付。

### 0.4 与一期翻译的关系

| 维度 | 一期（卷级顺译） | 二期（朝代知识补全） |
|------|------------------|----------------------|
| 底本 | 母本 `paragraphs[]` 顺译 | 无母本；维基【核心】+ 锚点 + 史学共识 |
| 交付字段 | `翻译详情` | 同字段名，同展示入口 |
| 文体目标 | 完整、流畅、有据 | **同**：完整、流畅、可读；**另加**专题原创叙事 |
| 原文入口 | 有 | 无（`原文字句` 不填） |

## 一、知识类型分界

| 类型 | 本质 | 生产模式 |
|------|------|----------|
| 人物七类 | **实体**（谁） | 一期：著作卷抽取 |
| 事略 / 典制 / 论著 | **朝代知识** | 二期：朝代 + LLM 史学共识 |

画布分工：

- **人物**：这个朝代有哪些关键人物（人物标签 = 个人名片）
- **事略**：这个朝代发生了哪些完整故事（时间刻度）
- **典制**：这个朝代定下了什么规矩
- **论著**：这个朝代留下了什么作品与思想

## 二、生产原则（强制）

### 1. 广角生成，后视镜去重

| 阶段 | 是否使用一期人物索引 |
|------|----------------------|
| Step 1–4 朝代研究 / 三类候选 / 字段填充 | **禁止**作为生成上下文 |
| Step 7 gate 去重与重叠审查 | **允许**只读对照 |

一期索引代表「著作里写到了谁」，不是「朝代全部重要知识」。二期生成须基于**史学界主流共识**，不受已抽人物条限制。

### 2. 无原文字句

二期条目不填 `原文字句`；`paragraphs[]` 留空。  
`母本著作` = `"朝代补全"`。  
小程序详情页对 `shilue` / `dianzhi` / `lunzhu` **不展示原文入口**。

### 3. 尽量求全，优先级控展示

不设朝代硬配额；宽进候选，gate 只删无效/互斥/重复主条目。  
画布密度由 **P0–P3** 过滤（见 `朝代优先级规则.md`）。

### 4. 试点朝代

首期试跑：**五帝**（`朝代ID` = `CD_HX_WUDI`）。内容量相对可控，便于跑通全流程。  
试跑验证通过后，其他朝代**直接按 Workflow 跑完**，不必为每个朝代单独维护正反例表（见各补全规则 §正反例说明）。

## 三、Workflow（标准流水线）

> **执行纪律**：三类**分步**产出候选与字段；详情**逐条**撰写。禁止 `--step all` 一口气跑完。详见 `执行纪律.md`。

```text
Step 0  加载朝代上下文（朝代.json）
        ⚠️ 不加载史略索引_01至02.json

Step 1  research（单次 LLM）
        → 05/朝代知识补全/{朝代}_研究报告.md

Step 2  candidates-shilue（仅事略，单次 LLM）
Step 3  candidates-dianzhi（仅典制，单次 LLM）
Step 4  candidates-lunzhu（仅论著，单次 LLM）
        → 05/朝代知识补全/{朝代}_候选清单.json（分步追加，勿三类同 prompt）

Step 5  人工审核候选

Step 6a fill-shilue / fill-dianzhi / fill-lunzhu / fill-renwu（每次仅一类）
Step 6b compose-detail（每条一次 LLM，禁止批量）
        → 事略/典制/论著/人物 均通过 compose-detail（规则自动按分类选择 详情撰写规则 / 人物详情撰写规则）
        → 06/索引条目/{朝代}_事略典制论著.json
        → 06/详情/{史略ID}_{名称}.json

Step 7  gate + enrichment
        - 互斥去重、坐标、详情 verify
        - dynasty_priority.py --llm（DeepSeek V4 Pro，可小批）
        - peak_year.py --llm（同左，可小批）

Step 8  append + 双导入
```

LLM：**与优先级/峰值年同通道**（`HIST_LLM_PROVIDER=deepseek`，`DEEPSEEK_MODEL=deepseek-v4-pro`），但补全创作阶段遵守 `执行纪律.md` 的**更严节奏**。

脚本入口：`historiography-dynasty-knowledge/scripts/dynasty_supplement.py`

## 四、分类判定决策树（唯一分类）

每条候选按以下决策树**逐层判定**，分类结果唯一且最贴切：

```text
第一层：主语判定
  主语是人？ → 人物（不进三类）
  主语是朝代/国家/联盟层面的概念？ → 进入第二层

第二层：论著判定（边界最清晰，优先）
  有独立的文献/书名/理论命题，且成书/提出于本朝？
    → 是 → 论著（典籍/名篇/书画/思想子类）
    → 否 → 进入第三层

第三层：典制判定
  有制度化结构（强制落地、可述流程、有奖惩）？
    且制度实质在本朝存在（见 §四.2）？
    → 是 → 典制
    → 否 → 进入第四层

第四层：事略判定
  满足事略五要素（多方角色、有动作、有结果、有影响）？
    → 是 → 事略
    → 否 → 不建条
```

**关键规则**：
- 同一概念可同时满足典制和思想时 → **典制优先**（制度的强制落地比思想的影响力更确定）
- 典制 + 事略 同主题可并存（制度结构 vs 具体事件）
- 论著·思想子类与典制**同一概念不双条**（第一属性取典制）
- 通过上层判定的条目，不再进入下层

### 四.1 典制 vs 论著·思想（分界速查）

详见 `典制与思想分界.md`。

| 典制 | 思想 |
|------|------|
| 国家/联盟强制落地的规则体系 | 个人或学派的认知、价值主张 |
| 有官府、流程、奖惩 | 无行政强制，仅舆论认同 |
| 主语：治理规则 | 主语：理论学说 |

**禅让（修正）**：

- **禅让制** → 典制（联盟权力交接规则：推举、考察、摄政、即位）
- **尧舜禅让** → 事略（该制度下的一次具体实践）
- **儒家禅让观 / 天下为公** → 思想（挂提出朝代，如战国儒门；五帝不建）

### 四.2 典制年代判定原则：实质 > 命名

典制条目**不要求制度名称在本朝已被正式使用**。判定标准：**制度实质**是否在本朝有可描述的运作结构。详见 `典制补全规则.md` §1.2。

配套约束：
- 名称使用后世词汇的典制条目，详情 **转** 段必须说明名称的实际起源年代
- `边界备注` 标注「制度实质存在于本朝，体系化命名在×代」

### 四.3 典制跨朝代建条规则

同一典制概念**允许多个朝代各自独立建条**，不互斥。详见 `典制补全规则.md` §2.3。

核心原则：各朝条目聚焦本朝对该制度的独特贡献，通过起/承/合段形成制度史链条。

### 四.4 论著硬约束

- **成书/创作/提出之年**须落在本朝区间内（不是内容写到的史事年代）
- **典籍一书一条**，禁止《书名·篇名》按卷拆条
- 跨朝成书（如《尚书》归周）禁止挂错朝代

### 四.5 跨朝代归属（候选硬纪律）

**SSOT**：`reference/跨朝代归属规则.md`。

- 除**君王/诸侯**（以**即位年**定归属）外，一律以 **pick year** 判定进哪一朝：`峰值年` / 立国封制年 / 成书年 / 事件高潮年等，见该文档 §二。
- **候选与遗漏审阅**：若 pick year 落入相邻朝代（如秦），**不得**列入本朝（如战国）候选。
- gate 仍校验 `史略开始年`、`峰值年` 落在 `朝代.json` 区间内。

### 四.6 跨类去重

- ✅ **典制 + 事略** 同主题可并存（制度 vs 事件）
- ❌ **典制 + 思想** 同一概念不双条（如禅让制 vs 禅让思想 → 只留典制）
- ❌ 同类同名重复

## 五、与人物层的去重原则

- **允许关联，禁止双份主条目**

- gate 产出 `重叠审查表`：`keep` / `person_tag_only` / `merge_hint`
