# 人物补全规则（朝代知识 · 第四分支）

> SSOT：`dynasty_supplement.py` Step `candidates-renwu` / `fill-renwu`。  
> 分类枚举、年份语义继承一期：`historiography-annotate/reference/人物标注规则.md`、`人物年份规则.md`。  
> 去重别名 SSOT：`帝王别名.json`、`宗戚别名.json`、一期 `史略索引_01至02.json`。

## 一、定位

## 二、强制去重（最高优先级）

### 2.1 一期已有 → 禁止再补（最高优先级）

对照 `data/03索引标注条目/史略索引_01至02.json`：

1. 同 `朝代ID` + 同 `史略名称` → **跳过**
2. 候选名经**别名归一**后命中一期任一条目 → **跳过**（不论一期分类）
3. prompt 须**逐条列出**一期已标注人物 + 已知别名，并写明「禁止再补」
4. LLM 输出后脚本 **`filter_renwu_duplicates`** 二次剔除

别名归一链（按序）：

```text
候选名
  → 帝王别名.json（global）
  → 宗戚别名.json（global）
  → 帝王.json「帝王原名」反查标准名
  → 与一期史略名称 / 标准名比对
```

**禁止**用大模型以异名再建一条。典型禁止：

| 一期已有 | 禁止再候选 |
|----------|------------|
| 吕太后（宗戚） | 吕后、吕雉、汉高后 |
| 汉高祖（君王） | 刘邦、汉高帝、汉王 |
| 黄帝（君王） | 轩辕、轩辕黄帝（若一期已覆盖） |

**蕃祚同样适用本节去重**：对照一期索引，同 `朝代ID` + 同 `史略名称`（政权名/部族名/国名）→ 跳过。蕃祚**无需别名归一链**（政权名不存在本名/别名问题），但仍须在 prompt 中逐条列出一期已标注的蕃祚条目并写明「禁止再补」。

每条候选必填 `去重自检` 字段，说明未与哪条一期重复。

### 2.2 帝王表强制补全（仅真君王）

> **帝王.json 是补全白名单，不是去重黑名单。**
>
> 含义：帝王表里的君王，只要一期索引（含别名归一后）**不存在**对应条目，就**必须补全**。帝王表不是在说「这些人都已覆盖」，而是在说「这些人是正牌君王，缺了必须补」。
>
> 去重的唯一依据是一期索引 `史略索引_01至02.json`，不是帝王.json。

**不是**帝王.json 每一行都补，须同时满足：

1. 符合 `帝王命名规范.md` **君王准入**（史略分类 = 君王）
2. 名称对齐 `帝王.json`「帝王名称」
3. 一期索引（含别名归一后）**不存在**对应君王条

**禁止按帝王表补宗戚**（如吕太后、汉高后 — 已有一期「吕太后」宗戚条则跳过）。

后妃、太后、同姓藩王 → 一期有则跳过；无则走**择优层**候选，分类按 `人物标注规则.md`（多为宗戚）。

### 2.3 薄标注待补（merge 厚度门拒收）

`data/05工作流中间产物/薄标注待补全/registry.json` 记录一期已标注、合计 **<100 字**、**未升 GLBL** 的人物。

| 项 | 说明 |
|----|------|
| 与一期去重 | **不在 GLBL** → 不触发 §2.1 禁止再补 |
| candidates-renwu | 脚本注入优先候选（`补全来源=薄标注待补`） |
| 是否成稿 | **人审 + gate** 决定；**非 100% 自动补全** |
| 产出 | 新 GLBL + `母本著作=朝代补全` |

## 三、择优层（非帝王）

同时满足 **知名度** + **可写性** 方可进候选：

| 条件 | 说明 |
|------|------|
| 知名度 | 通史可点名；或本朝已建事略/典制主轴参与者（如皋陶、伯益） |
| 可写性 | 能定主要生平节点；能写满一期人物详情下限 |

硬排除：世系链一笔带过、纯酱油、一期已有（含别名）。

传说期人物（皋陶、伯益）：**允许补**；年份遵 `人物年份规则.md`（文臣：出生年～去世年；学界仅有活跃期可标传说并注 `边界备注`）。

## 四、候选产出节奏（LLM 指令）

**一次调用、分类串行、最终合并返回**：

```text
禁止一口气混列。必须按序加工，每类完成后再进入下一类：
  1. 君王 → 2. 宗戚 → 3. 宦官 → 4. 文臣 → 5. 武将 → 6. 庶众
（蕃祚 视朝代有无）

每类输出前须：
  - 列出本期候选
  - 标注「已有一期·跳过」及匹配名/别名
  - 标注「帝王表强制」或「择优推荐」
最终合并为一个 JSON 对象，键为六类数组。
```

### 4.1 六类定义（必须写入 prompt）

`candidates-renwu` prompt **必须**包含：

1. `人物标注规则.md` §二全文（定义 + 分类链 + 典型边界）
2. 一期已标注人物清单（含别名）
3. 硬性纪律：先定分类、每人一类、禁止别名重复

每类加工时重复强调**本类门槛**与**不属本类的边界**：

| 史略分类 | 对象 | 门槛摘要 |
|----------|------|----------|
| **君王** | 帝王、实质割据诸侯负责人 | 名称对齐 `帝王.json`「帝王名称」；即位～崩年 |
| **宗戚** | 宗室、后妃、太后、公主、同姓藩王 | 挂册封之君；非帝王表里的太后/藩王 |
| **宦官** | 阉人/内官/近幸主轴 | **不含**受宫刑士人（如司马迁） |
| **文臣** | 行政/刑名/外交/儒学/文学仕宦主轴 | 曾任官；本卷叙事主轴在文事 |
| **武将** | 军功/征战/将帅主轴 | 史名最著为武将时唯一归类 |
| **庶众** | 游侠、刺客、方士、商人、起义未称帝者等 | 非上述体系 |

分类消歧：`君王 ＞ 宗戚 ＞ 宦官 ＞ 文臣/武将 ＞ 庶众`（见人物标注规则）。

人审：运行 `export-review` 生成确认表 → 用户勾选 → 写入 `{朝}_人审批准.json`（`phase=candidates`）→ 再 `fill-renwu`（默认不写详情）。

> 人物详情撰写规范见 `人物详情撰写规则.md`（起承转合、六类侧重、记忆点优先原则）。fill-renwu 入库后，通过 `compose-detail` 逐条撰写详情（脚本自动按史略分类选择正确的撰写规则）。

## 六、人物标签（必填流程，与一期一致）

二期补全的人物条**与一期 500+ 人物条同样须有标签字段**，供首页名片/泳道展示。

| 字段 | 说明 |
|------|------|
| `人物标签` | 2～5 汉字；后世提及该人时的记忆锚点 |
| `人物标签判定理由` | 须点名判定对象 |
| `人物标签置信度` | 0～1 |

规则 SSOT：`historiography-annotate/reference/人物标签规则.md`（与 `person_tag.py` 一致）。

**生产节奏**（不与 fill 混写）：

```text
fill-renwu（索引字段 + 详情）
  → gate
  → enrich：dynasty_priority → peak_year → person_tag.py --llm
```

- `person_tag.py` 读取人物索引（含 `06/.../{朝}_人物.json`），批量判定标签
- 无合适锚点可**留空**，禁止硬凑「事迹不详」类元标签
- 事略/典制/论著条目不产人物标签（格式规范不变）

gate 人物专检：七类人物条须已跑 `person_tag` 或标签字段显式留空且有 `_人物标签留空` 标记。**补全出来的人物默认为重要条目，原则上都必须有标签**；只有确实无通行典故/标志性事件的边缘人物才允许留空（须附留空理由）。enrich 步骤结束后强制验证：缺失标签且无留空标记 → enrich 失败。

## 七、与事略/典制/论著关系

- 允许关联：人物详情可提及相关事略/典制，索引不重复
- gate 重叠审查：人物 vs 事略同名主题 → `person_tag_only` 或 `keep` 人审
