# 朝代知识补全 · 执行纪律

> SSOT：本模块所有 LLM 调用的**节奏与批量约束**。  
> 与 `historiography-annotate` 中 `dynasty_priority.py` / `peak_year.py` **共用 LLM 基础设施**，但**执行策略不同**。

---

## 一、与优先级 / 峰值年的关系

| 维度 | 优先级 `dynasty_priority.py` | 峰值年 `peak_year.py` | 朝代知识补全（本模块） |
|------|------------------------------|----------------------|------------------------|
| 任务性质 | 对已存在条目**横向定级** | 对已存在条目**标峰值** | **创作**候选、索引字段、详情正文 |
| LLM 提供商 | `llm.provider` → DeepSeek | 同左 | **同左** |
| 推荐模型 | `DEEPSEEK_MODEL=deepseek-v4-pro` | 同左 | **同左** |
| 温度 | 默认配置 | `temperature=0`（可重复） | fill 索引 `0`；详情：事略 `0.3`，典制/论著 `0.2` |
| 批量 | 按朝代分批（默认 ≤20 条/批） | 按分类分批（高风险 ≤5） | **禁止**三类混跑；**禁止**详情批量 |

**结论**：用的是**同一套 DeepSeek V4 Pro 通道**，不是另一套模型；但补全流水线必须**更慢、更细**，不能照搬优先级/峰值年的批量节奏。

---

## 二、强制节奏（禁止偷懒）

### 2.1 分步产出，禁止一次混跑

| 禁止 | 必须 |
|------|------|
| 一次 prompt 同时列事略+典制+论著候选 | **分三种**：`candidates-shilue` → `candidates-dianzhi` → `candidates-lunzhu` |
| 一次 prompt 混列人物与三类知识 | **人物独立一步**：`candidates-renwu`（一次调用六类串行，但禁止与三类同在一条 prompt） |
| 一次 fill 写完多类 GLBL 字段 | **逐一执行**：`fill-shilue` / `fill-dianzhi` / `fill-lunzhu` / `fill-renwu` |
| `--step all` 自动跑完全流程 | 仅允许**显式逐步**调用；`all` 已废弃 |

每完成一类，建议 **人审候选** 后再进入下一类。

### 2.2 详情逐条，禁止批量撰写

| 禁止 | 必须 |
|------|------|
| 一次 LLM 写多条 `翻译详情` | **每条一次** `compose-detail --entry-id GLBL_xxxxx` |
| 循环内无 verify 连续落盘 | 每条：蓝图 → 成稿 → `detail_verify` → 落盘 → 再下一条 |
| 失败条目静默跳过 | 失败**停批**，修复后从该条重跑 |

> 人物详情同样逐条执行（`compose-detail`），规则见 `人物详情撰写规则.md`。人物七类 + 事略/典制/论著三类 = 全部详情逐条，无一例外。

### 2.3 推荐完整顺序（五帝试跑）

```text
research
  → candidates-shilue   → export-review → ⏸ 用户确认
  → candidates-dianzhi  → export-review → ⏸ 用户确认
  → candidates-lunzhu   → export-review → ⏸ 用户确认
  → candidates-renwu    → export-review → ⏸ 用户确认
  → 写入 {朝}_人审批准.json（phase=candidates）
  → fill-shilue / fill-dianzhi / fill-lunzhu / fill-renwu（默认不写详情）
  → export-review --review-phase entries → ⏸ 用户确认
  → 更新 人审批准.json（phase=entries）
  → compose-pending --background（推荐：每条 compose-detail 自带锚点+verify+最多1次revise）
  → qa-detail --skip-review（批量 gate 前 Python 硬检；Kimi 审校可夜间批跑）
  → gate / gate-renwu
  → enrich / enrich-renwu
  → append + 双导入
```

**Agent 纪律**：见 `Agent执行纪律.md`。禁止跳过用户确认；禁止前台长时间阻塞对话。

`fill-*` **默认不**连带 `compose-detail`；须显式 `--compose-after-fill`（agent 禁用）。

## 三、LLM 调用规范

```bash
# 与一期 enrichment 相同的环境（项目 tools/openclaw-historiography/.env）
HIST_LLM_PROVIDER=deepseek
DEEPSEEK_MODEL=deepseek-v4-pro
DEEPSEEK_API_KEY=...
```

脚本通过 `llm.provider.run_agent_turn` 调用，**不得**在 Cursor 对话里批量代写后一次性粘贴多十条入库（试跑单条示范除外）。

**详情撰写温度**（`compose-detail`）：

| 史略分类 | temperature | 理由 |
|----------|-------------|------|
| 事略 | `0.3` | 叙事、画面感、适度幽默 |
| 典制 | `0.2` | 制度程序准确，少发挥 |
| 论著 | `0.2` | 文献主旨准确，少发挥 |
| 人物 | `0.3` | 人物刻画、性格复杂感、适度幽默 |

`fill-*` 索引字段填充固定 `temperature=0`。

## 四、脚本入口（分步）

```bash
cd historiography-dynasty-knowledge/scripts

# 1 研究报告（单次）
python3 dynasty_supplement.py --dynasty 五帝 --step research

# 2–4 候选（每次仅一类）
python3 dynasty_supplement.py --dynasty 五帝 --step candidates-shilue
python3 dynasty_supplement.py --dynasty 五帝 --step candidates-dianzhi
python3 dynasty_supplement.py --dynasty 五帝 --step candidates-lunzhu
python3 dynasty_supplement.py --dynasty 五帝 --step candidates-renwu

# 6 人审确认表（候选或索引产出后）
python3 dynasty_supplement.py --dynasty 五帝 --step export-review
python3 dynasty_supplement.py --dynasty 五帝 --step export-review --review-phase entries

# 7 字段填充（须先有 phase=candidates 的 人审批准.json；默认不写详情）
python3 dynasty_supplement.py --dynasty 五帝 --step fill-shilue --background

# 8 详情（用户批准索引后；后台批量）
python3 dynasty_supplement.py --dynasty 五帝 --step compose-pending --background

# 或单条
python3 dynasty_supplement.py --dynasty 五帝 --step compose-detail --entry-id GLBL_00xxx --dry-run
# → 查看 logs/prompts/GLBL_00xxx_compose-detail.txt（完整 prompt 快照，所见即所执行）

python3 dynasty_supplement.py --dynasty 五帝 --step anchor-research --entry-id GLBL_00xxx --dry-run
# → 查看 logs/prompts/GLBL_00xxx_anchor-research.txt

# 8b 质检（逐条）
python3 dynasty_supplement.py --dynasty 五帝 --step anchor-research --entry-id GLBL_00xxx
python3 dynasty_supplement.py --dynasty 五帝 --step wiki-fetch --entry-id GLBL_00xxx
python3 dynasty_supplement.py --dynasty 五帝 --step verify-detail --entry-id GLBL_00xxx
python3 dynasty_supplement.py --dynasty 五帝 --step review-detail --entry-id GLBL_00xxx
python3 dynasty_supplement.py --dynasty 五帝 --step patch-detail --entry-id GLBL_00xxx   # review fail/warn 时
python3 dynasty_supplement.py --dynasty 五帝 --step qa-detail --entry-id GLBL_00xxx      # 一键：锚点+verify+review

# 8c 内容展现测试（模拟小程序分段；可选探测 localhost API）
python3 dynasty_supplement.py --dynasty 五帝 --step test-display
python3 dynasty_supplement.py --dynasty 五帝 --step test-display --entry-id GLBL_00561

# 9 gate
python3 dynasty_supplement.py --dynasty 五帝 --step gate
```

`--dry-run` 仅预览 prompt，不调用 LLM。  
`--background` 后台执行并写日志，立即返回（agent 对 fill / compose-pending / enrich 应默认使用）。  
`--skip-approval` 仅本地调试，**agent 禁止**。

包装脚本：`./run_supplement_bg.sh 五帝 fill-renwu`

### 通识误标拼音就地修复（无需重跑 compose-detail）

```bash
python3 fix_pinyin.py --id-range 564 585          # 预览
python3 fix_pinyin.py --id-range 564 585 --apply  # 写回
```

规则：`dynasty_supplement_lib.clean_over_pinyin`（继承翻译规则七）；`gate` 同步拦截。

## 五、与 enrichment 的衔接（Step 7）

gate 通过后，对**已写入索引的条目**调用（与一期相同）：

```bash
python3 .../dynasty_priority.py <06合并后的索引或全量索引> --llm --dynasty-id CD_HX_WUDI
python3 .../peak_year.py          <同上> --llm --dynasty-id CD_HX_WUDI
python3 .../person_tag.py         <同上> --llm --dynasty-id CD_HX_WUDI   # 仅人物七类
```

人物补全条目与一期人物条**同样须跑 `person_tag.py`** 产出 `人物标签`（2～5 字）。事略/典制/论著不跑标签。

此处允许小批量（横向定级 / 峰值需要同朝上下文），**不适用于**候选生成与详情撰写阶段。
