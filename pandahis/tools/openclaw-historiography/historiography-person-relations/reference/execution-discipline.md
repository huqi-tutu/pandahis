# 人物关系补全 · 执行纪律（ECC）

## 核心原则

1. **SSOT 优先**：taxonomy 以 `关系数据整理提示词.md` 为准；字段以 `schema.md` 为准。
2. **证据优先**：写入依据只能来自项目 grounding（11 译文 / 06 详情 / 索引原文字句）；**禁止**凭通识记忆或对话模型记忆增补。
3. **逐人串行**：一次只完成一个 `{名称}关系表.json`，verify 通过后再下一人。
4. **Verify 门禁**：未通过 `verify_relations.py --strict` 的文件视为未完成。
5. **双目标**：存量修复必须同时完成 **数据补全**（有据关系写全）与 **呈现 schema 改造**（二级枢纽含好友、单字边标题、配偶支四级孙辈、互斥规则、新五类）。
6. **最小充分**：适用子类写全；不适用不建枢纽；不为凑层级编造节点；禁止孙辈/徒孙展开（除配偶→子女）。

## 禁止事项

- 禁止为非人物类史略建表
- 禁止一次 prompt 输出多人物合并 JSON
- 禁止 `关系层级` 为 `五级` 或更深
- 禁止跳过 grounding 直接改 JSON / 入库
- 禁止跳过 verify 直接声称完成
- 禁止只做旧表字段重排（换类别名）而不重新核对证据
- 禁止将同朝政敌与外部敌人混淆；私交写入 `好友` 而非 `同僚`
- 禁止沿用旧一级名：`师从`、顶级 `外敌`、`君臣`（新产出）

## 每人强制输入

| 优先级 | 来源 | 用途 |
|--------|------|------|
| 1 | `data/11新标注条目翻译/{GLBL}_*.json` | 主 grounding（v2 译文 SSOT） |
| 2 | `data/06朝代知识补全/详情/{GLBL}_*.json` | 可选加厚 |
| 3 | 索引 `原文字句` / 简介 | 兜底 |
| 参考 | 旧 `07/{名称}关系表.json` | diff 对照，非事实源 |
| 参考 | 同谱系已修复关系表 | 交叉核验，非单独依据 |

## Verify 严重级别

| 级别 | 含义 | 处理 |
|------|------|------|
| **CRITICAL** | 类别非法、层级超限、主题名不一致、ID 重复、链断裂、同类别同层级同标题重复、二级分类枢纽层级错误 | 必须修复 |
| **WARN** | 缺 `record_id`、简述过短 | 建议修复 |
| **INFO** | legacy 类别名（君臣 / 旧顶级外敌 / 师从） | 仅非 strict 模式 |

## 单人工作流

```
读 grounding（11 → 06 → 索引）
    ↓
relations.py compose-one --id GLBL_xxx
    ↓
DeepSeek v4 Pro 成稿（按类别分轮 + 失败重试；taxonomy/schema 注入 prompt）
    ↓
对照旧 07：补漏 / 删无据 / 删超深度
    ↓
写入 data/07人物关系/{名称}关系表.json
    ↓
verify_relations.py --strict
    ↓
失败 → 修订 → 再 verify
    ↓
import-one / --sync → box_graph_*
```

## 朝代批量工作流

```
筛人物清单（索引 × 朝代 × 人物六类）
    ↓
for each 人物:
    单人工作流
    append / rewrite manifest
    ↓
抽查 1–2 人关系 Tab 呈现（一级→二级枢纽→人物）
```

## 完成定义（Definition of Done）

- [ ] 文件位于 `data/07人物关系/{名称}关系表.json`
- [ ] 成稿所依据的 grounding 已读（非空则写入简述可追溯）
- [ ] 符合新五类 + 二级枢纽 schema
- [ ] `verify_relations.py --strict` 退出码 0
- [ ] 已 import 到对应 `box_id`
- [ ] 批量时 manifest 已更新
