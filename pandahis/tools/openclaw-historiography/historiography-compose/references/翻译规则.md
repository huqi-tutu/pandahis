# 史略翻译规则

> **唯一 SSOT** — compose 与 translate 共用本文件。  
> 风格参考：《明朝那些事儿》| 共十二条写作原则 + 上节流水线约定。
> 总目标：以母本为底本顺译，吸收索引补充与必要的有出处外部史料，完整、流畅、有据地呈现一个史略。

---
## 第零部分：流水线约定

> translate 编排器与 compose 手工翻译共用本节；**十二条原则见下文规则一至十二**。

### 执行优先级

规则发生冲突时，一律服从以下优先级（从高到低）：

1. **母本完整覆盖**（信息 100% 覆盖、句序不乱）
2. **逐句顺译**（不跳句、不提前、不延后、不重组结构）
3. **数据准确**（人物、事件、数字、年代不得编造或概括掉）
4. **多史料融合**（索引补充与外部补全按锚点融入，异说独立呈现）
5. **风格优化**（口语叙事、明朝那些事儿笔调）
6. **幽默表达**（自然观察，不硬塞；见规则一）
7. **延伸补充**（仅在有确凿史料且挂母本锚点时；见下文外部补全原则）

### 禁止事项

- **禁止 AI 文学腔**：历史长河、时代洪流、命运齿轮、拉开序幕、翻开新篇章、历史终将证明、注定、必然、毫无疑问等——文风应接近《明朝那些事儿》，不是现代 AI 散文。
- **禁止结构重组**：不做「先把背景交代清楚再讲正文」；开篇大段脱离母本另起叙事。
- **禁止无出处发挥**：外部补全、重要故事、关键评价必须有著作 + 卷/篇名。
- **禁止调和异说**：多史书记载不同时，禁止融合成一个版本；须母本先述，再独立交代《某书》之说（见规则四）。
- **禁止资料拼接**：无重复、无语义打架、无批注式【】、无百科体条目感。
- **禁止以破折号结尾**：段落末尾不得使用破折号（——）。破折号只能用于句中或句首，段落结束须用句号、问号、感叹号或冒号。

### 术语

| 说法 | 含义 |
|------|------|
| **母本** | GLBL 条目 `paragraphs[]` 中 `role=母本` 的 block，经段落索引召回得到的正文；`母本著作` 字段标明著作（如 `01史记`） |
| **补充** | 同一 GLBL 条目 `paragraphs[]` 内 `role=补充` 的 block（跨著作合并产物）；单源条目通常只有母本 block |
| **外部补全** | LLM 基于历史知识补入的其他著作故事、评论、差异化观点与必要上下文；必须标明具体著作与卷/篇名 |

### 顺译的定义

**顺译 ≠ 字对字直译。** 顺译指：

1. **句序守恒**：按母本原文先后推进，不跳句、不提前、不延后、不重组结构。
2. **信息点守恒**：母本每一句（plan 阶段段内拆句后的 M001、M002…）的意思都须传达，禁止遗漏人物、事件、地点、数字、评价、结论。
3. **表达可重写**：在信息点完整的前提下，用现代口语叙事（《明朝那些事儿》笔调）重写，允许压缩纯修辞性重复，禁止压缩实质信息。

段号（P1、P2…）来自段落索引，一行通常一段；**段内拆句**在 `source_plan` 的「母本逐句清单」中完成，不在召回阶段假设「一段 = 一句」。

### 文言虚词误读陷阱

上古文言中的**判断句结构词**（如「是为」「是谓」「是乃」等）极易被误读为专名的一部分。LLM 翻译时必须识别这类虚词结构，避免将连词/代词/判断词错当成地名、人名、官名的一部分。

**核心陷阱：「是为」≠ 名为「是为」**

「是」在上古文言中为**指示代词**（这/此），「为」为**判断动词**（是/成为/叫做）。「是为X」的语义结构 = 「这（就）是 X」「这就是 X」，**不是**「名叫『是为X』」。

**典型误译案例：**

- ❌ 《史记·五帝本纪》「葬於江南九疑，是为零陵」→ 误：「他的陵墓，也就是后世称作『是为零陵』的地方」—— 把「是为」当成零陵名称的一部分
- ✅ 正译：「葬在江南九疑山，这就是零陵」

**高频语法结构黑名单（翻译时必须逐条检查）：**

| 结构 | 含义 | 禁止误读为 |
|------|------|-----------|
| 是为 X | 这就是 X / 这就成了 X | 地名叫「是为X」 |
| 是谓 X | 这叫做 X | 术语名含「是谓」 |
| 是乃 X | 这便是 X | 人名含「是乃」 |
| 此之谓 X | 这就叫做 X | 把「此之谓」当作X的修饰前缀 |
| 命之曰 X | 命名为 X | 地名/官名含「命之曰」 |
| 号之曰 X | 号为 X | 称号含「号之曰」 |

**自检方法：**

写完每段顺译后，搜索 `是为` `是谓` `是乃` `此之谓` `命之曰` `号之曰` 等结构词——如果它们在译文中以引号包裹出现（如 `「是为零陵」`），几乎**100% 是误读**，必须改为指示/判断语义的白话表达。

### GLBL 入口与跨著作补充

当前翻译入口为**全局索引** `data/03索引标注条目/史略索引_01至02.json`（`GLBL_*`）。跨著作主/补关系已在合并阶段写入 `paragraphs[].role` 与 `source_entries[]`（见 `标注索引条目合并规则.md`）。

| 层级 | 做法 |
|------|------|
| **索引补充层** | 条目中 `role=补充` 的 block：只引入不同观点/评价或新增故事/视角；锚点插入、与母本去重 |
| **外部补全层** | **仍须积极使用**。LLM 结合其他正史、注释、史论中的故事、评论、异说，按锚点挂入母本对应位置 |

外部补全典型场景（须标出处）：

- 他书对同一人物/events 的**不同说法或评价**（母本先述，再「《汉书》则……」）
- 他书独有的**新故事、新细节、新视角**（与母本去重后融入）
- 母本缺背景、缺人物介绍、缺结局时，从他书补必要上下文

翻译阶段**不修改**合并段界；段界争议在标注/合并审计阶段解决。

### 召回纪律

1. 只使用编排器 `recall` 的 `blocks[].paragraphs[].text`（来源：`段落索引/*.json`），**禁止**对 `02二十四史拆分后/*.txt` 自行切分。
2. GLBL `paragraphs[]` **每 block 独立召回**，禁止同卷 min→max 合并；对齐 `recall_global_index_entry()` 的逐 block + role 语义。
3. **严格按 GLBL 标注的 `paragraph_from` / `paragraph_to` 召回**，翻译阶段不得自行扩缩段界；段界争议在标注/合并审计阶段解决。
4. 外部补全可以使用模型历史知识，但必须在译文中写明出处（著作 + 卷/篇名）；无法确认出处的内容不得写。

### 太史公曰 / 司马迁评述（仅翻译环节处理）

**标注环节不返工**：史略条目的段落界若已含「太史公曰」或论赞句（含 audit 报告的 `commentary_owned`），**不在标注阶段修改**；已 `exclude` 的亦保持不动。

**翻译环节须这样写**（母本召回中出现「太史公曰」、卷末论赞，或论赞句落在传主块末尾时）：

1. **直引并顺译**司马迁原文意思，保留其评价、感叹、史观，不得改成译者自己的盖棺定论。
2. **史家第三人称**：司马迁是《史记》的作者、后世读者眼中的史家，**不是**历史现场的参与者。 framing 用：
   - ✅ 「司马迁在《史记》中写到……」
   - ✅ 「司马迁在本传论赞中说……」
   - ✅ 「《史记》作者司马迁在这里评论道……」
   - ❌ 「司马迁说……」（易读成当时人在场发言）
   - ❌ 把论赞改写成司马迁与传主对话、或「司马迁亲眼看见……」
3. **与正文叙事分界**：论赞前可用一句轻过渡（如「写到这儿，司马迁在篇末加了一段自己的话」），随即引述原意；不要用论赞替代传主生平收尾。
4. **禁止译者元叙述**：不写「注意，这里太史公曰……」「下面需要翻译司马迁的评语」——直接按上款写出即可。

**示例：**
- ✅ 「事到这儿，《史记》的作者司马迁在篇末写了自己的看法：……（顺译原意）。」
- ❌ 「司马迁说，郭解其貌不扬，但天下人都仰慕他的名声。」——「司马迁说」太像在场者；宜改为「司马迁在《游侠列传》论赞中写道，郭解其貌不扬……」

### 翻译总流程

0. **前置引入**：在正文开头写一段引入（约 100-200 字），交代**阅读框架**（为何从这段原文读起、在全书/本纪中的位置），再自然过渡到母本正文。引入**不得**重复 M001–M003 将写的身世/品貌/早年（见 `前置引入禁区`）。引入内容仅限 `source_plan.前置引入素材`，不得编造。引入段不计入母本覆盖检查。
1. **母本顺译**：以 `母本著作` 的召回段落为底本，按母本原文顺序推进；母本信息 100% 覆盖，句序不乱，这是文章骨架。
2. **索引补充融入**：如果索引中还有其他著作出处，只检查两类内容并插入母本对应位置：
   - **不同观点 / 评价 / 说法**：对同一史略有不同判断、评价、叙述角度，必须引入，并用「一说……」「《某书》则……」等方式交代差异。
   - **新增故事 / 新视角**：能更完整呈现史略主题的新情节、新细节、新视角，应融入；与母本重复的事实不重复写。
3. **外部知识补全**：母本段落上下文不完整、开头突兀、事件缺关键背景时，可以基于历史知识补全重要故事、评价和上下文；但必须标明出处（如《史记·项羽本纪》《汉书·高帝纪下》），不可无出处发挥。
4. **深度整理成文**：最终不是资料拼接，而是一篇历史研究者整理后的完整叙事：母本为主线，多源补强，外部补全只服务于流畅性和完整性。

### 两阶段成稿（translate 编排器）

编排器将 LLM 调用拆为两阶段，**规则在每次请求时通过 `rule_bundle` 全量注入**，质检仅作兜底：

| 阶段 | 产出 | 允许引用 | 要点 |
|------|------|----------|------|
| **Phase 1 `draft_mother`** | `{史略ID, 母本顺译}` | 仅母本（《史记》 framing 可） | 按 M 清单句序；按 `引用粒度` 句群/叙事引用；L0 禁释词不注释；禁止他书 |
| **Phase 2 `draft_enrich`** | `{史略ID, 翻译详情}` | 母本 + plan 中 `采用:true` 的他书 | 在锚点插入；只写异说/背景/细节/冲突；禁止重复母本；**前置引入**写阅读框架；**尾部**补本传缺漏退场 |

**外部补全准入**（plan 与 enrich 均须遵守）：仅当相对母本存在 **异说、冲突观点、必要背景、母本未载细节、评价差异** 之一时方可采用；与母本主体/事件/结果相同的内容视为重复，**不得**以外部补全再写一遍。

Phase 1 通过 `verify_mother_draft` 后方可进入 Phase 2。
Phase 2 通过 `verify_enrich_draft`（禁「据说/相传/传说」、白名单《》）后方可终检；失败自动重试 Phase 2，不重跑 Phase 1。

**必现词分级**：硬锚点（专名、数字、母本引号内原文）须在 Phase 1 用「」保留；软锚点（信息点）由 coverage 验收。**引用粒度**：并列排比须句群引用后统一解释，禁止四字一段碎引。**禁释词 L0**：崩/薨/卒/莫不从服等通识文言直接顺译，禁止「X就是Y」式注释。

### 内容层级与取舍

| 层级 | 来源 | 要求 |
|------|------|------|
| 母本层 | 索引 `paragraphs[]` 中 `work == 母本著作` 的召回文本 | **底本与主线**；100% 信息覆盖、句序不乱（见规则十） |
| 索引补充层 | 索引 `paragraphs[]` 中 `work != 母本著作` 的召回文本 | 只引入不同观点/评价或新增故事/视角；锚点插入、与母本去重 |
| 外部补全层 | 模型知识 + 可标明出处的史料 | 只补必要上下文、重要故事、评价；必须标明著作与卷；不得编造硬史实 |

不要按固定篇幅比例写作。母本决定文章主线和顺序；补充与外部补全按“是否让史略更完整、更有据、更顺畅”决定是否进入正文。补充与母本相同则不写；冲突则母本为准、句末引入异说。成稿须深度整理：一段一事、无重复、无语义打架。

### 外部补全与锚点原则

外部补全不是为了丰富篇幅，而是帮助现代读者顺畅理解母本。**仅允许**用于：

1. 母本缺少事件背景，导致无法理解事件发生原因
2. 母本省略关键人物介绍，首次出现需要一句说明
3. 母本直接进入事件，中间缺少承接
4. 母本没有记载最终结局，但正史明确记载，可补足收尾
5. 后世公认的重要历史影响，有助于理解人物地位

除此之外，不主动扩写。

**锚点原则（重点）：** 所有外部补全与索引补充，都必须依附于某一句母本；不能连续大段脱离母本另起叙事。补充结束后立即回到母本继续顺译；任何补充都不能长期脱离母本主线。

**补充内容三级：**

| 级别 | 内容 | 使用 |
|------|------|------|
| 一级（必须） | 背景缺失、人物介绍、地名解释、制度解释 | 读者看不懂母本时必补 |
| 二级（推荐） | 后续影响、同时代事件、重要评价 | 有确凿出处且挂锚点时 |
| 三级（慎用） | 学界观点、历史延伸、文化影响、后世故事 | 仅母本确实过短、且仍挂锚点时 |

### 重复判定

若**主体一致、事件一致、结果一致**，即视为重复，不得再写一遍。

只有出现以下**新增信息**之一，才允许再次叙述：

- 新细节
- 新评价
- 新时间
- 新原因
- 新史料观点

避免母本与补充史料只是换说法重复同一事实。

### 允许压缩（表达层）

**压缩的是表达，不是信息。** 母本逐句清单仍须逐句 √，禁止用「合并句」跳过母本编号。

**允许压缩：**

- 连续重复表达
- 连续同义修辞
- 礼貌套话
- 重复问答
- 不影响信息量的重复句

**禁止压缩（必须完整保留）：**

- 人物
- 事件
- 地点
- 数字
- 制度
- 历史评价
- 结论

### 产出格式（translate 编排器）

**产出目录**：`data/04史料翻译/`

**单条产出** — `data/04史料翻译/{史略ID}_{史略名称}.json`

固定三字段：

| 字段 | 来源 | 说明 |
|------|------|------|
| `史略ID` | GLBL 全局索引 / 编排器 | 条目 ID |
| `翻译详情` | LLM 撰写 | Markdown 正文 + 文末 `*参考著作：*` |
| `史料原文` | **编排器自动写入** | 段落索引召回的母本与索引补充原文；**不含** LLM 外部补全 |

`史料原文` 结构示例：

```json
{
  "说明": "段落索引召回原文；不含模型外部补全",
  "blocks": [
    {
      "role": "母本",
      "work": "01史记",
      "vol": "001",
      "volume": "五帝本纪",
      "source_file": "01史记_001_五帝本纪第一.txt",
      "paragraph_from": 1,
      "paragraph_to": 8,
      "paragraphs": [{ "id": 1, "text": "黄帝者，少典之子…" }],
      "text": "黄帝者，少典之子…\n蚩尤作乱…"
    }
  ],
  "text": "全文拼接（供小程序直接展示）"
}
```

**汇总产出** — `data/04史料翻译/史略翻译_汇总.json`

聚合目录下全部单条 JSON（不含中间产物目录）。每条 verify 通过或执行 `translate.py aggregate` 后自动重建。结构：

```json
{
  "schema": "historiography-translate/v1",
  "updated_at": "ISO8601",
  "count": 0,
  "entries": [
    {
      "史略ID": "...",
      "史略名称": "...",
      "翻译详情": "...",
      "史料原文": { "blocks": [], "text": "..." }
    }
  ]
}
```

`entries` 按 `史略ID` 升序排列。无需飞书、多维表格或其他二次导入步骤。

### 喊数（动笔前一行，**不得写入翻译详情**）

动笔前可在回复中自检一行（**禁止**写入 JSON 的 `翻译详情` 字段）：

`本条 N 段（母本 X + 索引补充 Y）；母本逐句清单 M 句；外部补全仅限可标出处内容；已读完 N/N 段。`

### 分块翻译（长史略自动启用）

当 **总段数 ≥ 15**、**单域超过 12 段** 或 **母本总字数 ≥ 10000** 时，编排器自动分块（默认每块 ≤12 段、≤6000 字）：

## 规则一：风格定位

**核心：** 以《明朝那些事儿》的笔调写历史叙事。不是学术论文，不是文言翻译，也不是百度百科式的条目介绍。是用现代人的语言讲古代人的故事，语言要生动流畅，像跟朋友聊天一样自然。

**为什么这条规则存在？**
最早一批翻译文章写得像教科书——冷冰冰地转述原文，读起来像「黄帝是少典的儿子，姓公孙，名叫轩辕。他生而神灵，弱而能言。他以干戈征讨诸侯，打败了炎帝和蚩尤」——没有场景感，没有人味。

**具体要做到：**
- 用日常口语的语气，「就像你在饭桌上跟朋友讲这个历史故事」
- 偶尔用现代比喻（如「相当于后来的朝廷会议」「这要放今天早被撤职了」），但不要过度现代化——不要把孔子说成CEO
- 用短句制造节奏：「结果呢？九年过去，水一点没治好。」
- 用自然的转折：「然而好日子没过多久，一个大麻烦来了——洪水。」
- **表达克制，收着写。** 幽默感应该来自历史事实本身的反差、荒诞、巧合——不是来自形容词和程度副词。程度副词（"居然""简直""可真是""实在是"）要慎用，白描已经足够有力时，不加修饰。

**语言节奏：**
- 长短句交替，不要全是长句子
- 关键转折用破折号（——）制造停顿感
- 适当用反问让读者有参与感

**引号规范（硬约束）：**
- **史料原文引用** → 直角引号「」：如「生而神灵，弱而能言」「习用干戈」
- **人物对话/口语叙述** → 弯引号“”：如尧说“鲧负命毁族，不可。”四岳说“试试嘛，不行再换。”
- 术语/概念（非原文引用）→ 弯引号“”：如“禅让”“封禅”
- 书名/篇名 → 书名号《》：如《史记》《汉书》
- **禁止**原文引用使用弯引号，禁止人物对话使用直角引号

**绝对避开的书面词与 AI 腔：**
「此外」「与此同时」「值得注意的是」「综上所述」「堪称」「可谓」「不啻」「则是」；以及「历史长河」「时代洪流」「命运齿轮」「拉开序幕」「翻开新篇章」「历史终将证明」「注定」「必然」「毫无疑问」等——这些词一出现，文章的明朝味儿就没了，像 AI 散文而非历史叙事。

**译者隐身（同P0硬约束）：**
用户阅读的是《史记》，不是译者。禁止在正文的任何位置出现译者的声音、评论、引导语：
- ❌ 禁用：「我们来看看」「今天要聊」「在这一段中」「各位读者」「下面我们来」
- ❌ 禁用：「值得注意的是」「令人惊叹的是」「不可思议的是」等译者感叹
- ❌ 禁用：画面外旁白套话作为整篇第一句话。判断标准：这句话是在给读者做阅读导航，还是在推进叙事？
  - 旁白套话示例（必禁）：「在《史记》的叙述序列里」「在司马迁的笔下」「纵观五帝时代」「翻开历史的长卷」
  - 叙事搭建示例（不禁）：「在黄帝与帝喾之间，颛顼做了三件大事」「在颛顼的时代结束之后，五帝的谱系翻到了新的一页」
- ✅ 正确：第一句话直接切入内容——要么是人物定位句，要么是《史记》原文首句。
- ⚠️ 注意：不禁「在」字本身，禁的是「译者在帮读者画路线图」的旁白姿态。自然叙事中以「在」起头的时空定位是正常的写作手法。

**首字铁律（违反即P0硬失败）：**
`翻译详情` 正文（跳过前置引入段）的第一个汉字**必须是**汉字（非标点、非数字、非英文、非markdown标记）。禁止正文以 #、##、###、-、* 开头。

**示例：**
- ✅ 好的：「轩辕的办法很简单但也粗暴——『习用干戈』，练兵备战，谁不来朝贡就打谁。这招效果立竿见影，诸侯们纷纷投降归顺。」
- ❌ 坏的：「轩辕采取了军事手段进行征讨，这使得诸侯纷纷归附。」

### 幽默规范

明朝那些事儿的幽默不是硬塞笑话，而是**看到历史中人的荒诞、无奈、心酸、巧合时，自然流露的观察和感叹**。

**好的幽默（自然观察）：**
- 「结果呢？九年过去，水一点没治好。注意这个时间跨度——九年。在那个生产力极其落后的时代，一个工程拖了九年没结果，这要放在今天早被撤职了。」—— 自然感叹，有历史观察
- 「象一脸尴尬，说『我思舜正郁陶』——我正在想念你，正难过呢。舜说『然，尔其庶矣』——嗯，差不多行了。」—— 场景本身的荒诞感
- 「从玄嚣到蟜极，这两代人都没当过天子。按说黄帝的子孙多的是，帝位不一定轮到高辛这一支。但高辛偏偏从侄子颛顼手里接过了帝位。」—— 历史巧合的观察

**不好的幽默（硬塞笑话）：**
- 「尧也很无奈地说『我也想杀了他，但不行啊』」—— 强行编台词
- 「黄帝一看，这蚩尤也太嚣张了，二话不说就冲上去干他」—— 太轻浮
- 「这家伙居然……」「这位爷可真是……」—— 口语化代称连着用 + 程度副词堆砌 = 油腻

**原则：** 幽默是调味料不是主菜。不能每段都追求幽默。主菜是正史叙事。如果一个地方没有自然产生幽默感，就不要硬加。

**克制的分寸：**
- 译文里**事实本身就足够精彩**，不必用形容词去强调它精彩
- 读完一段你可以感受到"这事挺有意思"——但不要替读者说"你看这事多有意思！"
- 好的效果：读者读完之后会心一笑。坏的效果：读者读的时候觉得译者一直在旁边戳他

**密度控制（每篇1-5个幽默点）：**
- **每篇译文 1-5 个幽默点**，均匀分布在不同章节，不要扎堆
- **短篇（1000字以内）：1-2个**，长篇（1000字以上）：3-5个
- **幽默不能影响正史的严肃性**——涉及以下内容时不加幽默：帝王驾崩、战争伤亡、制度建设的核心论述、人物盖棺定论的评价
- **如果一段话本身已经足够有力（如"终不以天下之病而利一人"这种），不要加幽默去稀释它**

**分布原则：**
- 开篇不玩幽默（读者还没进入状态）
- 结尾不玩幽默（需要庄重收束）
- 幽默放在中段，用于调节节奏——比如一段紧张的政争之后，或者一串枯燥的制度描述之后

### 幽默示例（实践中积累，供参考不强制套用）

1. 「别的婴儿忙着哭和吃奶时，他就能开口说话了；别的孩子还在撒尿和泥的年纪，他的思维就已经敏捷得像个小大人了。」（写黄帝）
2. 「九年过去，水一点没治好。注意这个时间跨度——九年。在那个生产力极其落后的时代，一个工程拖了九年没结果，这要放在今天早被撤职了。」（写鲧）
3. 「象一脸尴尬，说『我思舜正郁陶』——我正在想念你，正难过呢。舜说『然，尔其庶矣』——嗯，差不多行了。」（写舜的家庭悲剧）
4. 「舜的儿子商均也不成器——历史总是惊人的相似。」（写舜的后代）
5. 「从玄嚣到蟜极，这两代人都没当过天子。按说黄帝的子孙多的是，帝位不一定轮到高辛这一支。但高辛偏偏从侄子颛顼手里接过了帝位。」（写帝喾）

## 规则二：结构完整

**核心：** 每篇文章必须有头有尾。从人物的出身、家世背景开始讲起，按时间顺序推进到主要事迹、重要事件，最后到去世和身后事。不能虎头蛇尾，不能写到一半就没了。

**具体要做到：**
- 开篇：家世出身 + 关键背景（时代背景）
- 中段：主要事迹按时间线展开，重要事件详细写，可以做一些知识补充
- 结尾：去世时间/地点 + 身后影响/继承

**开篇定位判断（适用于事迹相对简略的过渡性人物）：**
对于功业记载不如同期帝王丰富，但世系位置关键的过渡性人物（如帝喾、少昊），开篇的使命不是"客观介绍"这个人，而是回答一个读者会自然产生的疑问："这个人功业不大，为什么要读他？"好的开篇是：
- 要么给出一个定位判断（如"帝喾是上古帝王世系中一个极为关键的连接点"）
- 要么点出他的独特矛盾（如"颛顼夹在黄帝和帝喾之间，常常被一笔带过——但司马迁给他的评价极高"）
- 要么揭示他的后世影响（如"商、周两代的始祖都出自他的血脉"）

不要求开篇写得像史学论文，但要求读完第一段后，读者知道"这个人为什么值得花时间了解"。

**如果没有去世信息怎么办？**
句式可以自然收尾，如「关于XX此后的记载就少了」「XX之后，《史记》没有再记载他的后续事迹」。

**短条目叙事铁律（母本 < 10 句时）：**
短母本的翻译最容易变成「逐句翻译+注释汇编」。必须保持起承转合：
- 补充材料只能挂母本锚点，不得打断母本原有的叙事推进节奏
- 外部补全的段落总数不得超过母本句数
- 段落之间必须有叙事承接句（如「但帝喾真正重要的不是这些生平标签，而是……」），杜绝「此外《某书》还记载……」的拼接感



### 内容延伸（结构完整补充规则 · v3.7 新增）

**核心：** 让故事有头有尾、有画面感，但**一切延伸必须服从执行优先级第 7 位**，并遵守第零部分「锚点原则」——挂母本句、补完即回主线，不得开篇大段脱离母本另起叙事。

**开篇延伸：**
- 只能在母本第一句对应位置，用一两句点出时代背景或后文关键；不得先于母本顺序写大段背景
- 延伸来源：母本即将展开的内容、同卷后文、有出处的正史记载
- ✅ 示例：紧接母本首句后——「这话在中国人的集体记忆里分量很重：后世的姓氏、农桑、历法、医药，追溯源头时总会回到黄帝这个时代。」

**中间延伸：**
- 对于有理解门槛的描述，挂对应母本锚点补充背景（见规则八六类触发）
- ✅ 示例：黄帝有二十五个儿子，其中得到姓氏的有十四个人——这话透露出上古时代"得姓"不是一件随便的事，"姓"是一种政治身份，不是每个儿子都有的。

**收尾延伸：**
- 仅在母本末句或对应锚点后，基于史实补人物/事件影响；须有出处或正史依据
- ✅ 示例：比干收尾「后来周武王伐纣成功后，做的第一件事就是封比干之墓。在中国文化里，比干被后世尊为『谏臣之祖』」
- ✅ 示例：禹的收尾「从禅让到家天下，从「天下为公」到「老子传儿子」，中国历史翻开了新的一页。禹是最后一个选出来的天子，而启是第一个生出来的天子，这其中的微妙变化，改变了此后几千年的政治格局。」

**延伸铁律（不可违反）：**
- ✅ 只能引用确凿史实——《史记》原文、同时代其他正史记载、学界公认史料
- ❌ 不能瞎编历史事件 — 没见过的事不能写
- ❌ 不能幻想人物心理活动 — 不要替古人加内心戏（除非原文本身写了）
- ❌ 不能生拉硬扯不相干的典故 — 不要为了好看硬凑
- ❌ 不能强行升华、灌鸡汤 — 事实本身够有力了，不需要你替读者总结「人生道理」

**无延伸材料时：**
如果该条目确实没有史实内容可延伸（信息太短、孤例），就忠实顺译原文，不强拉硬扯。宁可收得干净利落，也不画蛇添足。

## 规则三：内容完整性与数据准确

**核心：** 人物姓名、字号（如有）、家世出身、关键事迹、重要事件、性格特点、历史影响、去世时间/地点，一个都不能少。数字、年代、数据必须精确保留，不做概括、不编造。

**数据精度：**
- 原文写「九岁」→ 写「九年」，不写「好几年」「很久」
- 原文写「一年成聚，二年成邑，三年成都」→ 完整保留三阶段的递进，不简化为「很快就发展起来了」
- 原文有具体年份（如「践帝位三十九年」）→ 引用并保留
- 不确定的数字要说明是「大约」「据《史记》记载」
- 年代、时长等数据，原文没有不编造

**历史评价：**
- 不能自己"脑补"历史评价 — 不能说「这是中国历史上最重要的时期」除非原文或公认史学界这么认为
- 不能虚构史料信息 — 不确定的地方写「疑似」「推测为」「一说……」
- **禁止编造无出处的人物关系：** 任何人物的亲属称谓（子、孙、父、母、兄、弟等）必须直接来自母本或补充史料原文。即使是推测性关系，也必须标注出处（如"一说……""《某书》推测……"）。不确定的亲属关系，宁可空着不写，绝不编造。反例：「颛顼命令自己的孙子重管天事」——"孙子"关系在《国语》原文中无明确记载。

## 规则四：原文融入与引用规范（核心之一）

**核心：** 把母本与补充史料的关键原文自然地穿插在白话叙述中。不是每句原文都要引——信息用自己的话叙述，只在真正有冲击力、能体现判断差异或关键细节的原文才引用。禁止使用任何形式的显式引文标记（如【】）打断阅读流。

### 引用触发条件

**以下内容不引用原文、不写「某书原文说」，直接用白话叙述：**
- 人物姓名、字号、家世来源 — 例：「黄帝姓公孙，名字叫轩辕」（不是「《史记》原文说他姓公孙名曰轩辕」）
- 基本身份、官职、封地 — 例：「尧的父亲是帝喾，母亲是陈锋氏的女儿」

**以下情形可以引用原文并注明出处：**
- 品质/能力描述 — 例：「《史记》原文说他仁德『如天』、智慧『如神』」
- 金句 — 情感冲击力强、千古流传的句子（如「终不以天下之病而利一人」）
- 关键历史判断 — 如「天下明德皆自虞帝始」
- 原文表述本身极其精妙、不可替代 — 如「动静之物，大小之神，日月所照，莫不砥属」

**自检口诀：** 这句引用是在引人物姓名/家世来源/基本身份吗？如果是→去掉「《史记》原文说」，直接叙事；如果不是→可以保留。

### 引用优先级

同一史略内若多处可考虑引用，按以下优先级选择（避免为引用而引用）：

1. **名句** — 情感冲击力强、千古流传
2. **历史评价** — 盖棺定论、关键判断
3. **原文精彩表达** — 精妙、不可替代的措辞
4. **多版本差异** — 母本与补充史料说法不同
5. **其他内容** — 全部用白话叙述，不引

### 真实性优先（多史料异说）

当多个史书记载不同时：

- **禁止**融合成一个「折中版本」
- **正确**：先按母本正常叙述；再补充「《某书》则认为……」「《某书》记载……」
- 不同史料彼此独立呈现，不人为调和

**异说保留硬约束（违反即P0硬失败）：**
母本段落或索引补充（source_plan）中已列明的异说版本，必须在译文中全部呈现，禁止选择性遗漏。这是信息完整性的必要条件，不是"锦上添花"。
- 例如：绝地天通在《国语·楚语下》和《尚书·吕刑》中的不同记载——若source_plan同时标注了两种说法，翻译时必须两者都呈现。
- 自检方法：写完译稿后，对照 source_plan 中所有标注了异说的条目，确认译文中每条都对应有叙述。

### 引用出处标准化

引用原文或外部补全时必须指明著作名；外部补全还必须能写出卷/篇名，不能只说「有资料说」「原文说」：
- ✅ 母本引用：「《史记》原文说『生而神灵』」
- ✅ 补充差异：「《尚书·尧典》则把重点放在尧命羲和观象授时」
- ✅ 外部补全：「这一背景可参看《汉书·高帝纪下》」
- ❌ 错误：「有资料说……」「原文说……」「据说……」
- ✅ 例外：叙事性转述（如「桀临死前说『吾悔不遂杀汤』」）— 人物对话，非作者引用

### 三种自然引出的方式

1. 「按《某书》的写法/说法，……」—— 最常用
2. 「《某书》原文说『……』——」—— 引出较短的原文
3. 「《某书·某卷》补了一层意思：……」—— 引入补充或外部补全

### 引用频率与选择

逐句顺译的本质要求是覆盖每一句原文的信息，但这不等于每句都要用"引用→翻译"的格式。大部分内容用自己的话叙述，只在关键处引用。

**引用判断标准：**
- 信息性语句（事件、动作、流程）→ 用自己的话叙述，不引用原文
- 表现力语句（金句、比喻、强烈情感、关键判断）→ 引用原文，让它闪光

**引用频率：** 引用数量随篇幅与史料价值调整。长篇通常控制在 10-15 处左右；短篇只保留最关键的原文、异说或评价，不为凑数引用。

**引用选择口诀：** 这句话如果不引，读者会损失什么？只损失了「知道原文怎么说的」→ 不需要引；损失了情感冲击力或历史判断的精确性 → 必须引。

### 正确做法示例

- ✅ 「刚生下来就透着灵气。《史记》原文说『生而神灵，弱而能言』——别的婴儿还在忙着哭和吃奶的时候，他就能开口说话了。」
- ✅ 「《史记》作者司马迁在这里用了一句很震撼的话：『动静之物，大小之神，日月所照，莫不砥属。』——只要是日月能照到的地方，没有不归属他的。」（第三人称史家，不用「司马迁说」）

### 错误做法（严禁）

- ❌ 显式引文标记【】— 任何情况下都不得使用【】作为引文标记
- ❌ 「《史记》原文说：『黄帝者，少典之子。』就是说，黄帝他爹是少典。」—— 批注式结构
- ❌ 每句都引一遍原文再翻译—— 像翻译作业，没有阅读连贯性
- ❌ 「引原文→解释→引下一句→再解释」的循环模式。这种写法不像文章，像注释集。识别标志：连续三个段落都以「《史记》原文说/记载/写道/用XX概括……意思是/也就是说/换句话说……」起头。
  - 反面案例：「帝喾高辛，是黄帝的曾孙。他的父亲叫蟜极。《史记》原文记作"高辛父曰蟜极，蟜极父曰玄嚣，玄嚣父曰黄帝"。不过，从玄嚣到蟜极，这两代都没能坐上天下共主的位置，《史记》原话叫……按辈分算，高辛是颛顼的族子，《史记》原文说……」
  - 正面案例：「帝喾高辛的身份可不一般，按《史记》的写法，他是黄帝的曾孙。我们倒着推一下：高辛的父亲叫蟜极，蟜极的父亲是玄嚣，玄嚣的父亲正是黄帝。不过有个细节很有意思——从玄嚣到蟜极，这父子俩都没坐过天子之位……」

### 执行纪律

- 写完后全文搜索【——如果搜索结果>0，说明违规，立即改掉
- 全文搜索「原文说」「原文叫」「原文写」——检查是否在引姓名/家世/基本身份。只有这几种情况才违规
- 没有例外。任何情况下都不得使用【】作为引文标记

## 规则五：人物刻画

**核心：** 把人当人写，不神化不矮化。写出人物的性格、弱点、矛盾和决策过程。

**具体要做到：**
- 好人不写成完人。比如尧——他英明但也犯了用人不当的错误（鲧治水）
- 坏人不写成脸谱。比如桀——要写出他为什么能成为暴君，他的能力、性格中的毁灭性
- 决策过程要写出纠结和无奈。例如尧不想用鲧但四岳坚持，最后妥协了——这才是真实的政治
- 人物的内心挣扎在正史有暗示的可以合理推测，但不能虚构原文没有的内容

**示例：**
- ✅ 「尧说：『鲧负命毁族，不可。』四岳说：『试试嘛，不行再换。』尧就听了四岳的话，让鲧去治水。结果呢？九年过去，水一点没治好。这不是尧的错，是四岳坚持推荐的。但尧作为君主，承担了用人不当的责任。」—— 写出了尧的无奈和担当
- ❌ 「尧英明神武，慧眼识人，从不犯错。」—— 这是神化

**人物指代多样化：**

同一个历史人物在文章里会反复出现，不能每次都叫同一个称呼。全篇禁止无节制只用「他」代指，需姓名、身份、代词轮换；描述性代称（这家伙 / 这位爷）单篇全文总计不超 3 次。

**指代策略（按优先级选用）：**
1. **直呼其名**（尧、舜、轩辕）—— 最常用，最自然
2. **官职/身份**（这位天子、这位尚书、这位部落首领）—— 讨论政绩和政务时优先用
3. **代词**（他、其）—— 连续叙述同一个人的多个动作时用
4. **描述性称呼**（这家伙、这位爷）—— 仅在需要强调人物某个特质时用，**同一人物在同一篇文章里最多出现一到两次**

**轮换原则：**
- 同一人物在同一段落内，描述性称呼最多出现一次，其他用姓名或代词
- 不同段落可切换指代方式：讨论政绩时用官职，讨论私德时用姓名，讨论性格缺陷时可用描述性称呼（但限一次）
- 一句话里如果已经出现了人物的姓名，同一句话内不要再用描述性称呼重复指代

**示例对比：**
- ❌ 「这家伙从小就不一般。这家伙长大后更是不得了。这位爷打仗那是一把好手。」—— 一段里换了三次称呼指同一个人，读着像说书
- ✅ 「轩辕从小就不一般，长大后更是不得了。打仗方面，这位首领是一把好手。」—— 姓名 + 代词 + 身份，自然轮换

## 规则六：纯叙事

**核心：** 从头到尾保持叙事体，不出现小标题、分节号、列表符号。

**正文首段格式（硬约束）：**
- **首字符铁律：正文第一个字符必须是汉字，禁止以任何标点符号、书名号《》、引号「」“”、井号#、星号*、破折号——等开头。**
- 正文（不含前置引入）的第一段不得以 markdown 标记（#、##、###、-、*、>）开头
- 正文不得出现任何形式的 markdown 标题行（如「### 尧本纪」「## 主要事迹」）
- 正文第一句话必须是叙事句，不是译者评论句（如「我们今天要聊的不是一个神话，而是……」）



### 前置引入

正文开头必须有 1-2 段前置引入，交代**阅读框架**（为何从这段原文读起），**不是**重复母本开头的身世/品貌小传。引入后须有自然过渡句进入母本顺译。引入应像故事开头而非百科条目，写出厚度感，不碎。

引入素材来自 `source_plan.前置引入素材`（结构化字段），并遵守 `前置引入禁区`（来自母本 M001–M003 必现词），禁止自行编造或提前写母本首句内容。

过渡句举例：
- 「让我们来看一看《史记·五帝本纪》是如何描述黄帝的。」
- 「关于他的身世，《史记·五帝本纪》有一段简要的记载：」
- 「这一切，得从武丁即位说起。《史记·殷本纪》写道……」

**绝对禁止：**
- 「第一，……」「第二，……」「首先……其次……再次……」
- 「一、人物背景 二、主要事迹 三、历史评价」这种分节结构
- 「下表汇总了该人物的各项信息」这种表格提示
- 任何形式的显式目录或分段标记

**用自然方式过渡：**
- 「尧最大的功绩不是这些场面上的话，而是他做了一件对后世影响极其深远的事——定历法。」
- 「舜即位后做了一件大事——组建了上古时代最强内阁。」
- 「但舜的家庭悲剧并没有因为他出名而结束。」

**段落节奏：该合则合，该分则分**

每句话都单独成段会让阅读体验变得很碎，像在看聊天记录而不是读文章。段落应该是一个完整的叙述单元，不是一句话。

**什么时候该分段：**
- 场景切换（如从历法切换到继承人问题）
- 话题转换（如从尧转到舜执政）
- 时间跳跃（如从让位到去世）
- 需要一个呼吸停顿让读者消化的时候

**什么时候不该分段：**
- 同一场景内的连续对话（如尧和四岳的几轮问答，合在一段里更自然）
- 同一事件的连续叙述（如舜的考核阶段，多个子项合为一段）
- 一句话讲完不需要强调的过渡句（如"然后他做了更细的分工"这类句子，应该并入上下文，不要单独成段）

**原则：** 段落之间用自然叙事衔接，不要用 `---` 或其他分隔符号。章节内部每段3-8句话为宜。写完通读一遍，如果感觉像在刷屏，那就是分太碎了。

## 规则七：注音标注

**核心：** 首次出现的生僻字、多音字在括号内标注拼音。常见字不标注。后续出现同字可不再标注。

**格式：** 只标注生僻字部分，常见字不标
- ✅ 正确：嫘（léi）祖 — 嫘是生僻字，祖是常见字，不标
- ✅ 正确：颛顼（zhuān xū） — 两个字对大多数人都生僻，整体标注
- ✅ 正确：帝喾（kù） — 只标生僻字「喾」，「帝」是常见字不标
- ✅ 正确：有扈（hù） — 只标生僻字「扈」，「有」是常见字不标
- ❌ 错误：帝喾（dì kù） — 「帝」是常见字，不该标
- ❌ 错误：有扈（yǒu hù） — 「有」是常见字，不该标
- ❌ 错误：重华（chóng huá） — 「重」「华」都是常见字，不需要标注

**禁止注音后再注读音（冗余）：**
- ❌ 错误：荤粥（xūn yù，这两个字念"熏预"，是后来匈奴人的祖先）
- ✅ 正确：荤粥（xūn yù，后来匈奴人的祖先）
- 拼音本身就是读音，不需要再用"念…""读作…"解释一遍

**叠词（重叠词）只标一次：**
同一个生僻字连续出现两次（如叠词），只标注一次拼音，不要重复标注。
- ✅ 正确：嶷嶷（nì）— 两个「嶷」是同一个生僻字，标一次
- ❌ 错误：嶷嶷（nì nì）— 重复标注，多余

**常见不需注音字（标注前先检查）：**
有、氏、高、祖、父、母、子、女、公、伯、仲、叔、季、王、帝、侯、城、山、水、河、江、海、天、地、日、月、大、小、上、中、下

**常见需注音字（仅标生僻部分）：**
- 嫘（léi）祖、颛顼（zhuān xū）、帝喾（kù）、有扈（hù）、葷粥（xūn yù）
- 罴（pí）、貔（pí）、貅（xiū）、貙（chū）、夔（kuí）、皋陶（gāo yáo）
- 绌陟（chù zhì）、嶷（nì）、蟜（jiǎo）极、娵訾（jū zī）氏
- 饕餮（tāo tiè）、梼杌（táo wù）、螭魅（chī mèi）
- 璿玑玉衡（xuán jī yù héng）、姒（sì）氏、妫汭（guī ruì）、瞽（gǔ）叟、嚚（yín）

**速查口诀：**
- 只标生僻字，常见字不管 — 「帝喾（kù）」不是「帝喾（dì kù）」
- 叠词只标一次 — 「嶷嶷（nì）」不是「嶷嶷（nì nì）」
- 人名整体判断 — 「颛顼」两字都生僻→全标，「重华」两字都常见→不标

## 规则八：六类触发条件（含现代地名标注）

**核心：** 写作时遇到以下六类情况，必须自动触发对应处理——不允许说"忘了""没注意到"。

**一、制度类 → 解释制度背景**
- 「禅让」→ 上古时代特有的权力传承方式，天子传给最有德行的人，而不是自己的儿子
- 「封禅」→ 古代帝王在泰山等名山举行的最高规格祭天仪式
- 「巡狩」→ 天子定期巡视诸侯的制度，考核政绩、统一历法
- 「五刑」→ 墨（脸上刺字）、劓（割鼻）、剕（砍脚）、宫、大辟（死刑）
- 「四岳」→ 不是一个人，而是一群部落首领组成的议事机构

**二、地名类 → 标注现代对应位置**
格式：「幽陵（今北京以北一带）」「妫汭（guī ruì，今山西永济的妫水河畔）」。
- 仅限于确实知道的位置，不确定的写「约在今……」「一说在今……」
- 古今地名相同的不标（如「泰山」），知名地点不标（如「长江」），但特定河段要标（如「若水」→今四川雅砻江）
- 首次出现标注，后续不重复

常用地名对照：涿鹿→今河北涿鹿，空桐→今甘肃平凉崆峒山，幽陵→今北京以北一带，交阯→今越南北部，流沙→今甘肃西北沙漠地带，旸谷→今山东日照附近，昧谷→今甘肃一带，崇山→今湖南张家界一带，三危→今甘肃敦煌一带，羽山→今江苏连云港，妫汭→今山西永济，苍梧之野→今湖南宁远九嶷山一带，零陵→今湖南永州，岱宗→今山东泰山，江水→今四川一带，若水→今四川雅砻江

**三、人名类 → 首次出现时简要介绍**
「蚩尤」→ 最残暴的部落首领，「四岳」→ 部落首领议事机构，「羲和」→ 负责天文历法的官族

**四、器物类 → 解释是什么东西**
「璿玑玉衡」→ 上古天文仪器，类似浑天仪前身，「五瑞」→ 诸侯五种玉制信物，「六宗」→ 天地四方六种神灵

**五、事件类 → 补充事件背景**
「阪泉之战」→ 中国最早有记载的大规模战役之一，「涿鹿之战」→ 黄帝与蚩尤的决战

**六、补充信息类 → 标注出处**
- 补充内容必须标注出处：「背景补充——引自《文献名》」
- 短补充（一两句话，如「巡狩不是旅游，而是天子定期巡视诸侯的制度」）可以不出处
- 超过一个段落的补充必须有出处
- 不确定的地方写「疑似」「推测为」「一说……」，不能虚构

## 规则九：通假字处理

**核心：** 原文中的通假字、古今字，在首次出现时标注现行标准字；**已顺译为今字时，不再加通假标注。**

**格式：** 原文字（通「标准字」）或直接顺译
- 「说」→ 「说（通『悦』）」
- 「蚤」→ 「蚤（通『早』）」
- 「禽」→ 「禽（通『擒』）」
- 「脩」→ 「脩（通『修』）」

**原则：**
- 在不影响理解时可以顺译（如「脩身」直接写「修身」；「禽杀蚩尤」直接写「擒杀蚩尤」）
- 影响理解且保留原字时才标注（如「禽杀蚩尤」→「禽（通『擒』）杀蚩尤」）
- 不要每个通假字都标注，只标关键的
- 同一个通假字在一篇文章里只标一次

**硬规则（不可违反）：**
- **括号内外必须是不同字。** 禁止 `擒（通『擒』）`、`修（通『修』）` 等「A 通 A」的自相矛盾写法
- **二选一，不可叠加：** 要么保留原字并标注 `禽（通『擒』）`，要么顺译今字 `擒杀`——**不得**先改成今字再套通假括号
- 若需点明原字，用叙述句：`《史记》作「禽杀」，即擒杀蚩尤`

**错误示例：**
- ❌ `擒（通『擒』）杀了蚩尤` — 已顺译又标注，且内外同字
- ✅ `擒杀了蚩尤` — 顺译，不标注
- ✅ `禽（通『擒』）杀蚩尤` — 保留原字并标注

## 规则十：逐句顺译原则（灵魂规则）

**核心：** 这是整个翻译方法的灵魂规则，是所有规则中最重要的一条。

**全局史略（多 block）**：母本 block 仍须 100% 覆盖、句序不乱；补充 block 在母本锚点处融入，不得打乱母本顺序，不得重复叙述同一事实。外部补全只能放在不破坏母本顺序的位置，用来补背景、补重要故事或引入重要评价，并必须标明出处。

**为什么这条规则存在？**
早期的翻译方式是"意译"——先把原文读一遍，然后用自己的话概括大意。结果原文的叙事顺序被打乱，原文的细节被删减，原文的句式逻辑被重构。用户评价：「你写的不是翻译，是读书笔记。」

逐句顺译不是回到"硬直译"（字对字翻译，产出不忍卒读），而是在「完全意译」和「硬直译」之间找到平衡。

**三个层次的区别：**
1. ❌ **硬直译**：「黄帝者，少典之子」→「黄帝这个人，是少典的儿子」——翻译腔，不忍卒读
2. ❌ **意译（旧做法）**：「黄帝出身于少典部落，是当时最强大的领袖之一」——丢失了原文的精确信息和叙述顺序
3. ✅ **逐句顺译**：「高辛生来就不普通。《史记》原文说『生而神灵，自言其名』——和黄帝同款开篇，但多了一个细节：生下来就能说出自己的名字。」——保留了原文顺序、精确信息，但语言自然流畅

**具体规则：**

1. **不重新组织原文语句顺序。** 原文先说什么就翻译什么，原文后说什么就后翻译。不做「先把背景交代清楚再讲正文」之类的结构重组。

2. **每一句原文都要翻译覆盖，不能跳句、漏句。**
   - 不能因为某一句"不太重要"就跳过
   - 不能因为某几句"意思相近"就用合并句**跳过母本编号**（表达层压缩见第零部分「允许压缩」）
   - 每一句都要在逐句清单中有对应 √；行文可一句拆多句，或多句自然融在一段里，但清单编号须全部完成
   - ⚠️ **"覆盖每一句的信息" ≠ "每一句都要引用原文再翻译"。** 绝大部分信息用自己的话叙述即可，原文只在关键处引用。引用频率和选择标准见规则四

**100% 覆盖的定义：**

- 100% 覆盖 = **信息覆盖**，不是字数覆盖，不是句数覆盖
- **允许**：一句原文拆成多句表达；多句原文自然融合在一段里（清单仍逐句 √）
- **前提**：不能减少任何信息，不能改变母本顺序

**母本每句 Checklist（全部 □ 打勾后再写下一句）：**

- □ 顺序一致
- □ 信息覆盖
- □ 不提前
- □ 不延后
- □ 不跳句
- □ 不遗漏
- □ 不改变事实
- □ 清单编号已 √

3. **翻译语言要自然流畅，像在跟人讲历史。**
   - 但这不意味着可以跳句重组——流畅的前提是忠实于原文顺序

4. **母本、补充、外部补全要区分。**
   - 母本翻译：直接对应母本原文，保持顺序。
   - 索引补充：写在对应母本锚点处，用著作名说明差异或补充。
   - 外部补全：只补必要上下文/重要故事/评价，必须标明著作与卷，且不能喧宾夺主。

**强制性执行流程（取代"凭印象翻译"）：**

**步骤1：拆原文为逐句清单**
```
1.【帝尧者，放勋】→ 名字叫放勋
2.【其仁如天，其知如神】→ 仁如天神如
3.【就之如日，望之如云】→ 如日如云
...
N.【夫而后之中国践天子位焉，是为帝舜】→ 到中原即位
补充锚点：第 k 句后插入《某书·某卷》的不同评价/新增故事
外部补全：第 m 句前补《某书·某卷》的必要背景
```
这个清单只用于内部确认覆盖度，不写入正文。

**步骤2：逐句√着写**
对着清单翻译，翻完一句√一句。全部√完才提交。

**步骤3：三关自检**
① 覆盖检查：清单上的编号都√完了吗？
② 流畅度检查：全文读一遍，有没有批注式、分段式、【】式写法？
③ 细节检查：地名标注、注音、通假字都加了吗？

**判断口诀：** 如果你发现自己把原文前一句的内容放到了文章后半段，或者把原文后一段的内容提前到了前面，那就是违反了逐句顺译。

## 规则十一：完成标准（Definition of Done）

完成一篇文章时，必须**同时**满足以下全部项。写完后逐条勾选；写完一段可先自查一段，不要等整篇写完再回头补。

### 验收 Checklist

- ✓ **有前置引入** — 正文开头有 1-2 段引入，交代朝代身份定位，过渡自然；素材来自索引，不编造
- ✓ **母本 100% 覆盖** — 信息全覆盖，逐句清单编号全部 √
- ✓ **顺序完全一致** — 无提前、无延后、无结构重组
- ✓ **无漏句** — 无跳句、无因合并而跳过母本句
- ✓ **异说全部保留** — 对照 source_plan 中所有异说标注，译文中每条均有对应叙述
- ✓ **无重复信息** — 主体/事件/结果一致的不重复写（见第零部分重复判定）
- ✓ **无事实冲突** — 数字、年代、人物关系与母本一致；异说独立呈现不调和
- ✓ **引用全部有出处** — 外部补全与重要引用标明著作 + 卷/篇名
- ✓ **无现代 AI 腔** — 无历史长河、命运齿轮、注定、必然等（见规则一）
- ✓ **无百科体** — 不是条目罗列，是连贯叙事
- ✓ **无翻译腔** — 不是硬直译，也不是批注式「原文说……就是说……」
- ✓ **阅读体验像原创历史散文** — 不是翻译稿或资料拼接

### 写作后自检（8 项细则）

1. **母本覆盖** — 按规则十编号 √ 全部完成
2. **补充融入** — 只引入不同观点/评价或新增故事/视角；锚点插入、无重复拼接
3. **外部补全有据** — 标明具体著作与卷/篇名；无出处则删除
4. **行文流畅** — 无【】、无批注式、无书面腔、分段不过碎
5. **地名加注** — 古地名标注今地（规则八）
6. **注音加注** — 生僻字首次标拼音，叠词只标一次（规则七）
7. **引用自然** — 按引用优先级，不为凑数引用（规则四）
8. **文风词汇复检** — 搜索禁用词：此外、与此同时、值得注意的是、综上所述、堪称、可谓、不啻、则是，及 AI 腔词汇表，出现即改
9. **前置引入复检** — 第一段是否包含朝代/身份定位词？引文素材是否来自索引？过渡句是否自然？
10. **通假标注复检** — 禁止 `A（通『A』）`；已顺译今字不得再套通假括号（规则九）
11. **参考著作复检** — 逐条检查正文中引用的每一处外部史料出处，确认文末「参考著作」列表已全部覆盖。新增外部补全后必须同步更新参考著作列表。

## 规则十二：JSON 产出与汇总规范

**唯一交付物是 JSON，不再写入飞书。**

### 单条 JSON

1. 路径：`data/04史料翻译/{史略ID}_{史略名称}.json`
2. 字段：仅 `史略ID`、`翻译详情`（见第零部分产出格式）
3. 写入后须通过 `verify`（字段、字数、参考著作、禁词等）

### 汇总 JSON

1. 路径：`data/04史料翻译/史略翻译_汇总.json`
2. 每完成一条单条产出，编排器自动重建汇总；也可手动：`python3 translate.py aggregate`
3. `entries[]` 收录目录内全部有效单条，按 `史略ID` 排序
4. 单条 JSON 为 SSOT；汇总仅为只读聚合，便于小程序/数据库一次性导入

### 完整性

- 确认 JSON 可解析、无截断后再标记任务 `done`
- 长文（>2000 字）仍须保证 `翻译详情` 字段完整，不依赖外部平台防截断
- 汇总重建失败不覆盖已有汇总文件（保留上次有效版本）
